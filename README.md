# Пивовар — мастерская механик

Автономная адаптивная мастерская визуального конструктора с Telegram Login и тест-ботом. Для запуска нужен Node.js 18 или новее:

```powershell
node server.mjs
```

Настройки сервера лежат в файле `.env` в корне проекта. Впиши туда токен отдельного бота из @BotFather и его username без `@`. Для реального Telegram Login задай этому боту домен сайта в настройках Login Widget и укажи публичный URL в `PUBLIC_ORIGIN`; сайт должен открываться по HTTPS. Перезапусти `node server.mjs` после изменения `.env`. Без токена вход через Telegram и polling бота выключены; для локальной разработки нажми клавишу `/` трижды за короткий промежуток. Этот скрытый режим не создаёт Telegram-аккаунт и работает только в текущей вкладке. Не добавляй токен в исходники и не используй production-бота: тестовый бот должен быть отдельным, работать в личных чатах и не иметь доступа к игровым данным. Polling требует, чтобы на боте не был установлен webhook. `.env` и `data/` исключены через `.gitignore`; загруженные модули хранятся в `data/modules.json`.

### Cloudflare Worker и домен

Публичный адрес `piv-prog-site.shldsgd.workers.dev` — это **Cloudflare Worker**, поэтому этот проект нужно развёртывать как Worker, не как Pages. Сборка копирует в `dist/` только `index.html`, `app.js` и `styles.css`; Worker из `worker.js` обслуживает эти assets и проксирует запросы `/api/*` на Node API на VPS. `.env`, локальная база `data/`, исходники сервера и тест-бот в публичную статическую сборку не попадают.

1. Для подключения **без Tunnel и без своего домена** задай в Cloudflare **Workers & Pages → Workers → piv-prog-site → Settings → Variables and Secrets → Runtime** переменную `API_ORIGIN` со значением `http://79.137.202.111:4173`. Worker автоматически добавит DNS-имя `nip.io` к IPv4 origin, поскольку прямой подзапрос к IP Cloudflare блокирует (Error 1003); `nip.io` разрешается в этот же IP. Это прямой HTTP-доступ к VPS; он не шифрует трафик между Worker и VPS и годится только для теста. Не помещай значение только в Build variables: Worker читает runtime-переменную.
2. Для Git-based deploy создай именно **Worker**, подключи репозиторий и выставь Build command `npm run build`, Deploy command `npm run deploy`. Переменные `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` нужны в окружении deployment, если Wrangler деплоит из CI: токен должен иметь **Account → Workers Scripts → Edit** (и доступ к Workers/resources нужного account). Для Pages-проекта используется другое право и другой deploy flow. Локально сборку проверь `npm run build`; она не требует сторонних npm-пакетов.
3. На VPS в `.env` установи `HOST=0.0.0.0`, `PORT=4173` и `PUBLIC_ORIGIN=https://piv-prog-site.shldsgd.workers.dev`; токен оставь только в `.env`, перезапусти Node-сервер. Разреши входящий TCP `4173` в firewall VPS и в firewall панели провайдера (например, `sudo ufw allow 4173/tcp`, если включён UFW). После этого сам VPS будет напрямую доступен на `http://79.137.202.111:4173`. Никому не отправляй `.env` и не открывай другие порты без необходимости.
4. Для Telegram Login домен в BotFather оставь без схемы и пути: `piv-prog-site.shldsgd.workers.dev`. После deploy проверь `https://piv-prog-site.shldsgd.workers.dev/api/config`: ожидается JSON с `telegramConfigured: true`. Ответ 503 означает, что runtime `API_ORIGIN` отсутствует; 502 обычно означает, что Node-сервер не запущен, не слушает внешний интерфейс или порт закрыт.

**Важно:** прямое HTTP-соединение Worker → VPS не шифруется; используй его только для временного теста и не передавай через него чувствительные данные. Для постоянного использования включи HTTPS на VPS или вернись к Cloudflare Tunnel. Не используй Quick Tunnel одновременно, если `API_ORIGIN` уже указывает на публичный IP.

Для собственного домена назначь Custom Domain в настройках Worker и добавь его в BotFather; `PUBLIC_ORIGIN` тоже должен совпадать с используемым HTTPS-доменом. Не публикуй корень проекта напрямую — в `dist/` включены только браузерные файлы. Превью Worker локально: `npm run build`, затем `npx wrangler dev`.

### VPS через Termius (Ubuntu/Debian)

Termius — SSH-клиент, а не хостинг: сначала нужен VPS с публичным IP. Скопируй папку проекта на сервер через SFTP в домашнюю директорию пользователя (например, `~/piv-mechanics-studio`), затем подключись в Termius и выполни:

```bash
cd ~/piv-mechanics-studio
sudo apt update
sudo apt install -y nodejs npm tmux
node --version
chmod +x start_all_prog.sh
```

Если при запуске видишь `/usr/bin/env: ‘bash\r’: No such file or directory`, файл скопирован с Windows-переносами строк. Исправь его на VPS и повтори запуск:

```bash
sed -i 's/\r$//' start_all_prog.sh
chmod +x start_all_prog.sh
./start_all_prog.sh start
./start_all_prog.sh logs
```

`start` запускает сайт вместе с ботом, а `logs` только показывает вывод; `attach` подключается к уже существующей tmux-сессии и сам ничего не запускает. Сначала выполни `./start_all_prog.sh start`, затем при необходимости `./start_all_prog.sh logs` или `./start_all_prog.sh attach`.

Требуется Node.js версии 18 или новее (лучше 20+). Если `node --version` показывает меньшую версию, обнови Node.js перед продолжением.

Создай `.env` прямо на VPS (`nano .env`) и задай настройки, не публикуя файл и не отправляя его в чат:

```dotenv
TELEGRAM_BOT_TOKEN=ТОКЕН_ТЕСТОВОГО_БОТА
TELEGRAM_BOT_USERNAME=username_тестового_бота
PUBLIC_ORIGIN=https://твой-домен.example
HOST=127.0.0.1
PORT=4173
```

В BotFather настрой Telegram Login Widget доменом `твой-домен.example` (без `https://`). Направь домен DNS-записью A на IP VPS. Настрой HTTPS reverse proxy, например Caddy, и укажи ему передавать запросы на `127.0.0.1:4173`. Минимальный Caddyfile:

```caddyfile
твой-домен.example {
    reverse_proxy 127.0.0.1:4173
}
```

Установи Caddy из официального репозитория для своей Ubuntu/Debian, сохрани блок в `/etc/caddy/Caddyfile` и перезапусти его (`sudo systemctl reload caddy`). Открой на VPS входящие порты 80 и 443, чтобы Caddy выпустил HTTPS-сертификат. Сам Node-сервер не следует выставлять напрямую в интернет. После настройки DNS и HTTPS запусти сайт и Telegram polling-бот вместе:

```bash
./start_all_prog.sh start
./start_all_prog.sh status
./start_all_prog.sh logs
```

`server.mjs` запускает и веб-сайт, и Telegram-бот — второй отдельный процесс бота запускать не нужно. `tmux` оставляет процесс работающим после закрытия Termius. Управление: `./start_all_prog.sh restart`, `./start_all_prog.sh stop`; чтобы подключиться к консоли процесса — `./start_all_prog.sh attach`, выйти из неё без остановки — `Ctrl+B`, затем `D`. Для тестового бота удали webhook в BotFather/Telegram API, если он ранее был настроен: long polling с webhook одновременно не работает. Не запускай несколько экземпляров этого проекта с одним bot token.

До настройки домена сайт можно проверить напрямую по `http://79.137.202.111:4173`, но только если в `.env` выставить `HOST=0.0.0.0`, оставить `PORT=4173`, перезапустить приложение и разрешить TCP-порт 4173 в firewall VPS и у провайдера. Это временный HTTP-доступ: Telegram Login Widget требует публичный HTTPS-домен, поэтому для полноценного входа и активации механик настрой домен и Caddy как выше, затем верни `HOST=127.0.0.1`. Снаружи для HTTPS нужны порты 80/443, а 4173 публично открывать не следует.

Откройте http://localhost:4173. Холст расширяется по мере перемещения блоков; на компьютере карточки перемещаются ЛКМ, изменяются за правый нижний угол и соединяются перетаскиванием выхода на вход. ЛКМ по пустому холсту с протягиванием выделяет рамкой; Ctrl+ЛКМ (или Cmd+ЛКМ) добавляет блоки к выделению. ПКМ вызывает контекстное меню, а средняя кнопка панорамирует холст. Брошенный из библиотеки блок центрируется на месте отпускания. В инспекторе редактируются параметры, имя, ширина/высота и сворачивание блока до одной строки с названием и портами. Delete/Insert удаляют наведённый блок либо выбранную группу. Ctrl+Z отменяет, Ctrl+Alt+Z повторяет. Колесо плавно масштабирует относительно курсора в диапазоне от 0,1% до 100 000%; Alt+колесо перемещает горизонтально. Панель в правом верхнем углу холста содержит вписывание схемы, переключение привязки к сетке, выравнивание и видимость сетки. Шаг сетки настраивается в «Настройки». Кнопка «Помощь» в шапке показывает подсказки по всем жестам. Каталог разбит на пивоварские разделы — варка, инвентарь, пиво и опыт, достижения, рецепты и крафт, пивоварня, клан, профиль и игровые экраны; несвязанные с игрой экспериментальные блоки оставлены только для совместимости старых `.piv`. «Цепочки» добавляет готовые сценарии. Блоки «Создать вкладку…» сразу добавляют редактируемые разделы Инвентаря, Клана, Рецептов, Пивоварни или Профиля; их экран берёт начальные записи из базы проекта и открывается из настроек блока. На телефоне блоки добавляются нажатием, параметры открываются по нажатию на карточку. Черновик хранится в localStorage; через «Загрузка» можно импортировать и экспортировать модули `.piv`.

## Регистрация и Telegram тест-бот

- Вход в мастерскую закрыт до авторизации через Telegram Login Widget. Сервер проверяет подпись HMAC и актуальность `auth_date`, а сессию хранит в подписанной HttpOnly cookie.
- Нажми на кнопку аккаунта в шапке, чтобы увидеть Telegram-профиль (имя, username, ID и фото, если Telegram его передал) или выйти из аккаунта. Выход завершает серверную сессию; локальный режим разработчика также можно закрыть этой кнопкой.
- В окне файлов можно переименовать текущую механику, быстро отправить её в личный чат Telegram или нажать «Активировать в Telegram». Активация публикует версию и открывает deep link `?start=activate_<id>`: тест сразу запускается на сервере, отдельное подтверждение не требуется. Telegram не позволяет сайту прикрепить локальный `.piv` и отправить его от имени пользователя, поэтому тест-бот запускает сохранённую сервером версию. Для быстрой отправки в личку пользователь должен заранее нажать Start у бота.
- В боте доступны `/start`, `/menu`, `/help`, `/end`, кнопочное меню «Мои механики», загрузка `.piv`, запуск своих/доступных по ссылке схем и удаление собственных модулей. Во время активного теста бот сохраняет одно сообщение и редактирует его результатами; принимаются только slash-команды, объявленные блоками механики, callback-кнопки этой механики и `/end`. Прочие сообщения и команды игнорируются.
- Для теста бот создаёт отдельный синтетический профиль из базы проекта (инвентарь, запас пива в литрах, опыт пивовара, рецепты, достижения и клановый прогресс). Изменения живут только в тестовой сессии и сбрасываются при новом тесте/`/end`; они не записываются в игровые данные Пивовара. Каждый проход ограничен 50 действиями против случайного спама.
- В тест-боте исполняются условия наличия/поиска/количества предметов, пустоты инвентаря/категории, запаса пива/опыта, открытого рецепта, достижения и членства в клане. Условие выбирает соединение с соответствующим `outputKey`; предшествующие блоки изменения песочницы влияют на проверку.
- Для пробного запуска используй готовый [`degustation-demo.piv`](./degustation-demo.piv): в боте выбери «Импортировать .piv», отправь файл, затем нажми «Проверить». В механике `/tasting` предлагает выбрать сорт; callback-кнопки присылают отдельные ответы.
- Для безопасного теста используются личные чаты и синтетический игрок. Денежные/игровые операции не применяются к настоящей игре; неподдержанные блоки обозначаются как предпросмотр. Экспортёр/симулятор — не универсальный runtime-пивовара.
- Серверный API требует Telegram-сессию; режим разработчика открывает только интерфейс и не выдаёт серверных прав или доступа к API.

## Игровая база данных и формат файла `.piv`

Кнопка «Данные» открывает редактируемый тестовый контекст бота: профиль Telegram (имя, ID, username), уровень/литры пива/опыт/варки, инвентарь с количеством и категорией, рецепты с ингредиентами, достижения, клан с ID/ролью/участниками/заданиями и пользовательские переменные. Для пользовательской переменной задаются имя, тип («Текст» или «Число») и значение; переменные можно добавлять и удалять. В текстовых и числовых полях блоков кнопка «Вставить» вставляет `{имя_переменной}` в позицию курсора; в числовом поле токен заменяет текущее число. Подстановка выполняется в браузерном предпросмотре и в Telegram-тесте; старые `{{имя}}` сохраняют совместимость. Доступны системные имена `{player_name}`, `{player_id}`, `{user_name}`, `{user_id}`, `{username}`, `{level}`, `{beer}`, `{experience}`, `{brews}`, `{clan_name}`, `{clan_id}`, `{clan_role}`. Данные сохраняются в черновике и `.piv`; при тестировании используются только как синтетический профиль и не читают/изменяют настоящие аккаунты оригинального Пивовара.

Экспортируемый `.piv` — UTF-8 JSON-файл с версией проекта (`version: 1`) и схемой `piv-mechanics/1`. Граф механики содержит `nodes` и `connections`; `gameScreens` хранит экземпляры вкладок, а `gameDatabase` — базовые игровые данные проекта. Расширение помогает системе и пользователю распознавать модули Пивовара, а текстовая структура остаётся открытой для проверки, резервного копирования и будущей серверной валидации/runtime. Старые проекты `.json` продолжают загружаться и получают базу по умолчанию.

Кнопка «Тест» проверяет часть ограничений Telegram и симулирует поддерживаемый подграф на тестовом игроке в интерактивном чате. Можно нажимать inline-кнопки, отправлять объявленные в схеме команды и завершить её командой `/end`. Неподдерживаемые локальным симулятором блоки и ветвления без блока условия показываются как предупреждения; циклы, неверные команды и некорректные inline-кнопки — как ошибки. Браузерная симуляция не вызывает Telegram-бота.

## Возможности прототипа

- Библиотека блоков для Telegram-событий, управления варкой, пивом и опытом, предметами, достижениями, рецептами/крафтом, кланами, игровыми экранами и переменными пивовара. Пользовательские и системные переменные можно подставлять в текстовые и числовые поля блоков фигурными скобками, например `{player_name}`, `{beer}` или `{brew_count}`; старый синтаксис `{{имя}}` продолжает работать.
- Условные блоки для наличия/поиска/количества предметов, пустого инвентаря, запаса литров пива/опыта, открытого рецепта, достижения и членства в клане. «Если / иначе» сравнивает текстовые и числовые переменные (равно/не равно, больше/меньше, содержит/пустое) и имеет отдельные выходы «ДА» и «НЕТ». У каждого условия есть подписанные выходы: соединяй каждый со своей веткой действий.
- Поиск блоков по названию, группе и системному типу; категории можно сворачивать с сохранением выбора.
- Цепочки действий для приветствия, варки, ежедневной награды, покупки предмета и комбинированного крафта/инвентаря/клана.
- Самостоятельные игровые экраны-инстансы: инвентарь, клан, рецепты, пивоварня, профиль, достижения, задания, лавка, история варок и рейтинг. У каждого экрана редактируются заголовок, вкладки, строки содержимого и действия; экземпляры можно переключать и пробовать в интерактивном предпросмотре. Они сохраняются в `.piv` отдельно от графа блоков. Это настраиваемые демонстрационные представления типичных разделов, а не подключённые к оригинальной игре экраны или её реальные данные.
- Системная база данных проекта с количеством предметов, списком достижений, рецептами с ингредиентами, уровнем/запасом пива (литры)/опытом, кланом и произвольными переменными с типом «Текст» или «Число». Вкладки, созданные соответствующими блоками, связаны с данными этой базы и доступны для настройки в инспекторе.
- Каталог сгруппирован по предметным подкатегориям; часть общих Telegram/API-блоков скрыта из нового выбора, но остаётся доступна для открытия старых проектов.
- Перетаскивание/добавление с центрированием на точке отпускания и настройка блоков, точный размер и компактное сворачивание, множественное выделение рамкой, групповое выравнивание, привязка к сетке, изменение размера боковых панелей, совместимые соединения портов с анимированными линиями и пунктирной подсветкой перекрытых сегментов, бесконечно расширяемый холст, панорамирование и широкий диапазон масштабирования.
- Светлая и тёмная темы с сохранением выбранной темы на устройстве.
- Автосохранение, отмена/повтор действий (Ctrl+Z, Ctrl+Alt+Z), экспорт и импорт.
- Плавное масштабирование с привязкой к курсору, подробное редактирование без потери фокуса, тестовый прогон локального графа с предупреждениями об ограничениях симуляции и адаптивная навигация.

## Проверка совместимости с Telegram-ботом

**Сейчас механики конструктора не исполняются в Telegram-боте.** Экспорт — версионированный JSON-формат сайта (`schema: "piv-mechanics/1"`), но в текущем `piv-bot-tg/code` нет движка, который загружает этот формат, интерпретирует граф и вызывает обработчики. Бот использует `pyTelegramBotAPI` (`telebot`) и явно объявленные Python-диспетчеры команд/callback. Совпадение названия блока с возможностью Telegram не делает действие автоматически поддержанным ботом.

Чтобы включить будущий Telegram-тест, понадобятся отдельный серверный адаптер и тестовый контур:

1. Сервер принимает экспортированный граф, проверяет схему, типы/пределы полей, права автора и размер.
2. Валидатор строит граф исполнения, проверяет все ветки, циклы, команды и `callback_data` по ограничениям Telegram.
3. Runtime-адаптер сопоставляет ID блоков с конкретными функциями Пивовара и `telebot`; текущий отдельный тест-бот — ограниченная песочница предпросмотра, не runtime production-игры. Перед подключением реальных игровых систем необходимы явная поддержка блоков, права и отдельный тестовый контур.
4. Тест выполняется только с отдельным тестовым ботом/тестовым чатом и тестовыми данными, с журналом действий и защитой от начисления настоящих игровых наград.
5. Для callback-кнопок обработчик должен подтверждать callback query; имена команд регистрируются через тот же dispatcher, что и остальной бот.

Telegram Login Widget и серверная проверка подписи добавлены, как и отдельный прототип Telegram-тест-бота. Живой Telegram-вход/бот не активируются без токена и username настроенного бота; сами механики исполняются в ограниченном тестовом preview, а не в production runtime Пивовара. Совместное редактирование не подключено, секреты бота в клиентский код добавлять нельзя.
